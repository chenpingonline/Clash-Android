# Clash Android 需求与实施计划

状态：已开始实施。首个原生开发迭代的实现范围、构建方式与待完成项见 [开发说明](../README.md)。以下保留完整目标，不代表已全部实现。
日期：2026-10-23。

## 1. 已确认目标

1. 基于现有Clash项目开发原生Android客户端，尽量保留现有功能；仅因明确的平台限制做替代或能力裁剪。
2. UI采用第2组风格：节点优先、蓝色强调、紧凑列表；支持跟随系统、浅色、深色。
3. 五个主入口：首页、代理、配置、活动、设置。二级页采用返回导航，复杂编辑器全屏。
4. 功能需求以文字规范和现有代码为准；效果图的错字、示例值和类似控件不构成新的业务规则。
5. 默认免Root，本机运行代理；远程控制器是独立高级模式，不代替本机VPN。
6. 分阶段交付不等于删减总范围。只完成UI或核心闭环时必须注明未完成项，不能称作完整版。

设计依据：[主页面及功能规格](design/android-ui.md)、[二级页面画板](design/secondary/README.md)、[双主题与交互](design/secondary/theme-and-states.md)。

## 4. Android适配边界

- 使用VpnService承载本机流量接管。系统授权、单VPN冲突、用户撤销、服务重建、网络切换必须处理。
- 始终开启VPN与无VPN阻断通过系统设置配置；断开按钮在受系统控制时须解释状态。
- 分应用选择受包可见性约束。包枚举权限、工作资料及发布渠道要求在阶段0验证，不能承诺无条件列出所有包。
- 后台周期更新用WorkManager时最短15分钟，受系统调度影响。原项目5分钟更新不直接映射为后台保证；如保留运行期间短间隔，必须明确其仅在服务活跃时尽力执行，避免重复任务。
- fnOS文件扫描改为系统文件选择器；Shell环境变量、systemd、iptables/nftables、Linux网卡操作不移植进免Root本机模式。
- 不默认支持手机热点透明转发或旁路由。显式HTTP/SOCKS监听可保留，并独立验证LAN访问。
- UI与核心Go逻辑可分层复用，但不运行原Go Web/Root Helper当作Android宿主。
- 首版内核随应用更新。动态替换机制属于后续能力评估，不能用不可执行的下载文件假装升级成功。
- 所有平台限制必须列明原因与替代方式；复杂度高本身不构成删减脚本、规则集或YAML的理由。

官方依据：[VPN](https://developer.android.com/develop/connectivity/vpn)、[周期任务](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)、[包可见性](https://developer.android.com/training/package-visibility/declaring)。

## 5. 架构与复用方案

建议模块边界（不是要求一开始拆成大量Gradle模块）：

1. app：应用入口、导航、依赖组装、权限与主题。
2. ui/designsystem与feature：公共组件和各功能页面；仅消费状态与发出动作。
3. domain：配置应用、节点切换、规则操作、备份恢复等用例与数据契约。
4. data：订阅下载、数据库/文件、偏好、远程控制器、历史快照。
5. corebridge：Mihomo及Go配置处理桥接；受控生命周期、线程和错误映射。
6. vpn：VpnService、TUN文件描述符、socket保护/底层网络绑定、通知和状态机。

建议UI通过repository/use-case访问服务，禁止页面直接操作文件、内核或启动网络任务。mock与真实实现遵守同一接口；模拟模式必须明确标注，不能混入正式运行状态。

### 当前源码证据

只读检查Clash-Manager当前HEAD：`261050fe9b6c1d64ae387be5900228429b9816bd`。不自动把它作为Android最终依赖版本；集成时固定可复现提交并记录修改来源。

- `backend/internal/configyaml`已有YAML覆写、节点组和订阅增强；`profile_extensions.go`使用goja，脚本超时5秒。
- 已查明增强链局部顺序：订阅序列编辑 → 全局覆写 → 全局脚本 → 订阅覆写 → 订阅脚本。宿主设置与最终配置的整体先后关系仍需追踪调用方，不能仅凭这个函数假定完整管线。
- `backend/internal/ruleimport`包含INI、MRS、解析与导入规划逻辑，优先评估复用。
- `backend/internal/mihomo`是现有控制器客户端参考；Kotlin客户端是否重写取决于桥接契约。
- 原Vue UI及CodeMirror属于Web实现，Compose和原生编辑器需要新做。
- Go的`internal`包不能直接从无关模块导入。需评估在原模块内增加移动桥接入口或抽取公共包；任何跨仓库改动另行明确范围，不在本次文档任务中实施。

### 数据和配置事务

- 区分原始订阅、用户增强、草稿、最终生效配置和历史快照；每层有revision/时间与来源。
- 下载→格式解析→增强与脚本→Android兼容处理→内核校验→暂存→应用→确认状态→提交“当前配置”标记。
- 应用失败回到上次可用状态，保存失败原因及草稿；应用/恢复/自动更新共用串行通道，防止互相覆盖。
- Android必须管理的路由/监听约束集中处理，列出被拒绝或调整的字段。禁止静默改变节点、规则或脚本语义。
- 用户凭据不出现在URL日志、截图示例、诊断包或版本库；备份导出需明确是否包含凭据。

## 8. 实施前剩余决定

可先按本草案推进技术验证；下面事项在对应阶段固定，不为写文档提前阻塞：

- 最低Android版本及是否需要32位设备：默认建议Android10+、arm64；阶段0确认工具链和目标手机。
- Mihomo具体版本、桥接方案和Go公共逻辑复用方式：阶段0以编译和真机证据确定。
- 应用正式名称、包名、图标、签名归属、发布渠道：本地测试可用临时身份；正式打包前固定。
- 独立内核更新、二维码导入、应用图标切换：保留需求记录，明确渠道/实现能力；若无法实现说明原因，不以假控件交付。
- 本机连接应用归属、完整包枚举与远程规则开关：能力检测后呈现，无法取得时明确未知或不支持。
